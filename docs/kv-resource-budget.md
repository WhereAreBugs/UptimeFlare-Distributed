# KV 与 Worker 资源预算

公开首页继续使用持久 KV 快照，不将访客请求转成全量 D1 查询。遥测仍直接发送到既有采集器，不持久化到 KV。

## 发布策略

- 默认五分钟及更长间隔的目标：每五分钟最多一次正常发布，最多 288 次/UTC 日；原策略为 720 次/日，固定发布减少 60%。
- 内容指纹包含配置版本、暂停、样本时间、延迟、累计统计及时间推导的失联状态，排除快照生成时间。没有变化时不写 KV，每十分钟保留一次心跳。
- 存在开启且间隔小于五分钟的目标时，保留原两分钟快照频率。暂停的短间隔目标不提高发布频率。样本仍按目标间隔的两倍失联，不用延长探针失联时间来掩盖发布延迟。
- 故障阶段变化与恢复可通过既有 Coordinator 异步提前发布；正常上传/ACK 不等待发布。重复失败与旧积压不反复触发提前发布。此处的内存提示有界，不能替代 D1 权威状态。
- 管理配置保存仍使用独立配置覆盖键，保留版本比较与跨实例锁。配置保存本身不会因公开发布预算耗尽而失败；后续定时快照会跟上最新版本。

## 跨实例硬预算

两个公共 KV 键共用现有 D1 `public_snapshot_slot` 控制键。原数字槽位首次使用时在原键内更新，不需要迁移或新表；不为每条结果增加计数写入。

| 分类 | 每 UTC 日预留次数上限 |
|---|---:|
| 正常定时发布 | 720，默认五分钟配置实际最多 288 |
| 提前事件发布 | 144 |
| 配置覆盖发布 | 100 |
| 默认配置合计 | 532 |
| 短间隔配置合计 | 964 |

事件与正常测量发布之间至少间隔一分钟，重复/旧 Cron 槽位不能再次预留。KV 写入失败或返回不确定时仍占用预留，防止失败重试扩大消耗。UTC 午夜仅重置计数，保留已发布指纹与时间。预算是本项目新发布器的上限，不能覆盖账户其他项目、REST/控制台操作或部署当天旧代码已消耗的额度。

指纹在 KV 成功写入后才确认。写入失败保留旧 KV 内容，下个允许时机可以重试。默认模式下正常发布最多需要 576 次控制行更新，低于原有 720 次槽位更新；内容不变时不执行这些更新。除此之外仍有小范围元数据读取及配置/事件开销，不能将固定写入比例当作 D1 全账户节约保证。

## 缓存与过期

- 全站快照过期边界为 15 分钟，覆盖十分钟空闲心跳及缓存传播余量；各目标样本过期独立判定。
- KV 冷缓存并发请求合并为一组两键读取，边缘缓存一分钟。缓存不承担持久化，不使用内存计数作为配额账本。
- 默认页面两分钟刷新一次，短间隔目标保持一分钟；隐藏标签页停止轮询。公开轻响应允许浏览器缓存 30 秒。
- 公共目标历史边缘缓存一分钟，最多合并 16 个不同历史请求；先校验范围、配置版本和暂停状态。错误、管理配置及令牌接口不进入公共历史缓存；客户端历史缓存为 private 并按 Authorization 区分。
- 静态资源路由由同一份编译配置导出不含密码的布尔值与源码指纹。已验证公开构建仅 `/api/*` 进入 Worker；启用旧式页面密码或元数据缺失/不匹配时，全部资源继续经过鉴权 Worker。

## Cron

一分钟调度继续支持短间隔目标与告警宽限期限。正常快照仅在对应发布槽位调用 Coordinator；历史清理的 RPC/认领降为每小时，登录清理每十五分钟，调度清理每五分钟。未配置通知时只每十五分钟做残留任务清理；配置了通知时继续每分钟评估、重试，非必要清理改为每十五分钟。原有租约、暂停栅栏、事务、通知幂等及真实队列不变。

## 验证

覆盖真实 Miniflare D1/KV 的日预算、UTC 重置、并发及旧槽位拒绝、控制行升级、内容不变跳过、失败重试、短间隔失联边界、KV 并发合并与历史缓存。原生 Assets 路由测试证明 HTML/JS 为零 Worker 调用，管理员 API 仍返回 401；有页面密码的构建保持全路径 Worker。

完整 Worker/客户端/部署测试及五类产物验收包括管理分组越权和撤销、大量目标按需历史、Coordinator 重放、持久 ACK 与 SRE 父子追踪链。生产验收另记于 `refactor-production.md`，不能以本地测试替代线上新样本和 ACK。
