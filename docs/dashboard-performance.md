# 首页性能与公开状态缓存

首页只读取目标的最新摘要，不加载全部历史。暂停目标不创建卡片，全部暂停的分组也不出现在首页；顶部的关闭数量仍包含暂停目标。分组默认折叠，每组每页最多展示 10 个目标。

历史按可见目标加载，同时最多发出两次请求。客户端最多缓存 24 个目标，五分钟后重新获取；离开屏幕或翻页后卸载旧卡片的历史与图表。折线图模块在展开目标时加载，隐藏页面停止自动刷新。

## 公开快照

生产部署为 Worker 和 Pages 绑定同一个 `UPTIMEFLARE_PUBLIC_KV`。设置 GitHub Actions 变量 `PUBLIC_KV_ENABLED=1` 后，部署脚本创建或复用公开状态命名空间。Cloudflare API Token 需要当前账户的 Workers KV Storage 编辑权限。

定时 Worker 每两分钟发布一次公开摘要，正常情况下每天最多 720 次持久快照写入。Pages 用一分钟的边缘缓存读取摘要；首页访问不会查询 D1。管理员、管理 Token、探针配置和数据接收仍使用 D1，公开快照不参与授权。

快照只保存公开展示字段。目标 URL、请求头、请求体、代理配置、通知配置、管理凭据不进入快照。保存配置后的公开更新受 KV 最终一致性和边缘缓存影响；授权与暂停操作本身仍由 D1 事务决定。

快照超过三分钟或只有配置而没有测量时，页面显示生成时间和数据暂时不可用提示，当前活跃目标变为未知。陈旧成功结果不会计为正常；暂停状态和已有历史保留。此时折叠卡片不自动请求历史，用户主动展开仍可尝试加载。

D1 免费套餐有账户级每日读取额度，超过额度会拒绝查询。公开快照可继续展示，但管理员操作、实时结果接收与历史查询仍受 D1 可用性限制；独立探针保留未成功提交的本地数据。参考 [D1 定价](https://developers.cloudflare.com/d1/platform/pricing/) 和 [KV 配额](https://developers.cloudflare.com/kv/platform/limits/)。

## 部署与验收

部署记录 `init.sql` 的摘要及其数据库绑定。相同数据库、相同结构不会重复执行初始化或扫描全部短期历史来重建每日汇总。首次安装、结构变化或更换数据库仍执行初始化。已有部署的一次性结构验证需要同时匹配 `D1_VERIFIED_SCHEMA_HASH` 和 `D1_VERIFIED_DATABASE_ID`，不能用于跳过其他数据库的初始化。

`scripts/dashboard-smoke.mjs` 使用实际 Pages 产物、100 个目标、300 个探针分配及约十万条历史记录验证摘要查询、历史延迟加载和暂停过滤。`scripts/public-cache-smoke.mjs` 在没有 D1 绑定的环境中验证公开 KV 快照与权限边界。所有验收使用虚拟配置、虚拟凭据和临时存储。
