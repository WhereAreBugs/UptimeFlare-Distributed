# 相同失败合并与 D1 行数验收

2026-10-05。新失败按探针、目标和 UTC 日合并，同一连接阶段、错误码及公开原因只存一份；时间使用精确的起点、步长、次数序列。不连续和不规则采样拆成多个序列，迟到样本排序后重新编码。成功样本不填充失败时间；断网、离线空缺及系统故障不推断为目标不可达。

## 数据与兼容

复用已有 `probe_failure_events` 表，不修改 schema，不执行生产历史全表转换。合法目标 ID 不包含 `@`，合并行使用保留的 `@failure:v1:<monitorId>`，`stage=@packed:v1`；`time` 是 UTC 日起点加分块编号，`code` 保存块内最大实际时间，`message` 保存版本、样本数、分组及时间序列。这些存储标记只在内部使用，API 继续返回真实目标、阶段、错误码与每次失败时间。

每块最多 32 KiB UTF-8、4096 个失败，每个目标/探针/日最多 128 块；写入只重编码最后一块，单个 SQL JSON 参数限制为 256 KiB。读取有块数和 8 MiB 字节预算。损坏、未知版本、计数错误和容量超限会拒绝提交；原始结果、汇总、通知及回执继续受同一租约和事务保护，持久化成功后才 ACK。

不再写新的 `probe_bucket_stages` 行，累计阶段统计仍随每探针计数文档更新。过期清理从合并时间序列精确计算本次删除桶的阶段扣减，并与旧 bucket-stage 行合并。合并行必须等到整个 UTC 日过期且该日所有统计桶排空后才删除；分批清理及跨截止日不会丢失尚需扣减的统计。

既有逐次失败行继续按原索引查询，与合并行按原 API 的时间、目标、探针排序和游标混读。最近失败仍最多每分配 100 个，事故页面仍最多 100 个且可分页；不改变前端、默认采样周期、失败统计或完整私有原始结果。旧历史不会为这次优化触发高配额重写，随后按既有保留期清理。使用新合并格式后需运行兼容的服务端版本；离线工具拒绝恢复到忽略合并格式的旧 v1 代码。

## 同一虚构负载实测

结果为本地 workerd/D1 执行元数据，详见 [packed-failure-results.json](packed-failure-results.json)。基线 `b1ece02` 与新代码运行完全相同的独立夹具：1 个探针、16 个虚构目标、200 个样本，每目标相隔 300 秒，全部成功或全部失败，数据库每个场景重置。未查询或写入生产 D1。

| 场景 | 原读取 | 新读取 | 原写入 | 新写入 |
| --- | ---: | ---: | ---: | ---: |
| 全成功 | 541 | 541 | 480 | 480 |
| 全失败 | 945 | 559 | 1280 | 512 |

全部失败的总写入减少 60%，读取减少 40.8%。相对同场景全成功的额外失败写入从 800 降到 32，减少 96%；16 个目标/日文档代替 200 个失败明细和 200 个阶段桶行及索引。一天 288 个等间隔相同失败可以合为一组 `[0,300,288]`，该夹具的失败文档小于 256 字节，API 可还原全部 288 次失败。

既有包含 25 次失败的 200 条混合夹具：集中历史写入 142→92，集中新鲜结果 163→111，五分钟积压 563→467，重放始终零写入。

以上是具体负载结果，实时每五分钟的一次提交仍需更新每个受影响目标的日文档；跨日、原因变化、分块、通知和清理会改变成本，不能视为任意负载的固定比例保证。此次没有删除失败样本或提前 ACK。真实生产补传及配额计数仍在额度恢复后验收。
